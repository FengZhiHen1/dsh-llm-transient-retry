# DSR-001：以「事件化重试」挂 `agent/request-error` 作为恢复手段

- 日期：2026-10-14
- 状态：已接受（实现待做）
- 基线：DSH `dsh-v0.1.7-rc.2` / `477b4f42`，运行时 `0.1.7-rc.2`

## 背景

`openai-codex` 路由的上游过载报文被 `classifyPiAiError()` 归入 `PI_AI_ERROR`，而该码不在重试白名单，导致 turn 级失败（见 `../需求.md`）。需要在不改动 `dsh-llm-retry`（平台）与 `dsh-codex-subscription`（路由）的前提下恢复这类失败。

## 决策

新建独立插件 `dsh-llm-transient-retry`，作为 **Host 平面 bundle 行**，挂 `agent/request-error` waterfall：按 provider ∧ code ∧ **文本** 三层判据识别瞬态失败，按退避等待后返回 `{ kind: 'retry' }`，并写出标准 `llm/retry` / `llm/retry-started` 事件。

## 备选方案与否决理由

| 方案 | 结论 | 证据 |
| --- | --- | --- |
| **A. 零代码：改配置加白名单** | ❌ 不可行 | `[实测]` 本机 `--dump-config-schema`：`codex-subscription` 行 config 31 键中没有 `retryPolicy`/`retryableCodes`/`providers`。该路由的 profile 字面量硬编码在插件内（本机 2.2.2 的 lib 中 `retryPolicy` 命中 0） |
| **A'. 零代码：升级 2.6.8 + `retryPolicy: unlimited`** | ❌ 否决 | `[实测]` `unlimited` = `mode:"always"` ⇒ 无条件、**无上限**重试，且连 `AUTH`/`INVALID_REQUEST`/`CONTEXT_WINDOW_EXCEEDED` 一起重试。且 `always` 会静默丢弃 `retryableCodes`（`retry-policy.ts:186-191`），无法收窄 |
| **B. 静默重试（不写事件）** | ⚠️ 可行但次优 | 零不变量风险，但 GUI 无「正在重试」提示，用户只看到卡住。而 GUI 渲染节点已现成（`ui-chat/.../retry.ts`），放弃可见性没有收益 |
| **C. 事件化重试（本决策）** | ✅ 采用 | 判据面窄；合规性有**权威校验器**可自证（`dsh-llm-retry` 导出 `./invariant`）；GUI 免开发 |
| **D. 分类改写**（上游 2.6.8 的做法：包一层流，把报文改写成 `Network transport failure: …`） | 🔜 留作后续探针 | 最贴近上游且天然合规；但需自己 wrap `openai-codex` 的 adapter，与 `dsh-codex-subscription` 自己的 `compaction.wrapAdapter` 注册顺序关系**未验证**（`[推断]` 有冲突风险） |
| **E. 不改，等上游修正 `classifyPiAiError()`** | ❌ 不作为主路径 | 与本仓库 `references/connection-rpc-405-外部情报-2026-09-28.md` 记录的同类经历一致：上游 Issues 关闭、不接受外部 PR、无人回复。但不能因此把插件当长期替代——见「自然退役」 |

## 后果与约束

1. **必须严格遵守 `llm/retry` 不变量**：`fail` 是 throw（`invariants/src/index.ts:161`），不合规的 `session.append` 当场抛，且装机时复核已载入会话。⇒ `retry`/`retryId` 一律从会话日志推导，与校验器同源。
2. **不重试整个 `PI_AI_ERROR` 桶**：该码含 `pending`/`deferred` 两种非瞬态终态（`stream.ts:111-118`）。
3. **不介入已在白名单内的码**：避免与 `dsh-llm-retry` 双重重试。
4. **自然退役**：上游若修正分类表，三句报文将不再落 `PI_AI_ERROR`，判据自动失效——这是刻意接受的失效方式，插件不做版本探测。
5. **平台无关但不预先声称**：无平台相关代码路径，但只在实测实例范围内声明支持。

## 复核锚点（本决策何时会失效）

- `packages/llm/llm-pi-ai/src/stream.ts` 的 `classifyPiAiError()` 分类表被修改；
- `packages/llm/llm/src/retry-policy.ts:18-23` 默认白名单被加入 `PI_AI_ERROR`；
- `packages/llm/llm-retry/src/invariant.ts` 的事件契约变更；
- `packages/core/agent-loop/src/agent.ts:477-492` 的 `agent/request-error` 调度语义变更；
- `dsh-codex-subscription` 新增能表达 `retryableCodes` 的配置面。
